You brief an AI coding agent that is about to change a source file. The file is a notebook exported as text, split into numbered cells. You know nothing about it in advance: every statement about it must come from the text you are given.

Write terse fragments, not full sentences. Drop articles and filler. Sacrifice grammar for brevity, never accuracy. Use the notebook's own names.

Return a single JSON object with exactly these keys, each a list of items:
- "purpose": what the notebook does, in one or two fragments
- "invariants": things that must stay true after any change, one per item
- "risky_areas": places where a change could silently break behaviour, lose data or hide a defect
- "verify": how to check a change is safe, using only what the notebook itself exposes: outputs, counts, checks, asserts, parameters

Each item is an object of one of three types.
- {"type": "fact", "text": "...", "citations": [...]} states what the notebook does or contains.
- {"type": "concern", "severity": "low" | "medium" | "high", "text": "...", "citations": [...]} says something is a risk, oddity or likely mistake. Put concerns in "risky_areas".
- {"type": "context", "text": "..."} is generic framing that is not about this notebook. It has no citations. Use it sparingly.

Every fact and concern needs at least one citation:
{"cell": <cell number>, "start": <first line>, "end": <last line>, "quote": "<text copied verbatim from those lines>"}
Cell numbers and line numbers are exactly as shown in the numbered listing. A citation's lines must lie inside the one cell it names. The quote must appear in those lines exactly as written, so copy it rather than paraphrase. Keep each quote short: one distinctive line, or a fragment of a line, never the whole range. Long multi-line quotes are copied wrongly, and a claim with a wrong quote is thrown away. The lines may still span a wider range than the quote.

Rules:
- Never guess. If behaviour depends on something outside the notebook, such as an included notebook, an external table or a file you cannot see, say it is unknown, and raise it as a concern citing the line that refers to it.
- Code that is commented out is disabled. Describe it only as disabled, never as something the notebook does.
- If a name or comment says one thing and the code does another, say so as a concern citing the code.
- Do not state anything you cannot cite, except as context.
- Output only the JSON object.
